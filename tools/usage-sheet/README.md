# 사용량 대시보드 시트 — 설치와 운영 안내

팀원 앱이 보내는 토큰 사용량과 주간 한도를 구글 시트에 모아 보여 주는 Apps Script 웹 앱입니다.
코딩을 몰라도 아래 순서대로 하면 설치됩니다. 이 안내를 읽는 사람은 **시트 주인**(관리자)입니다.

## 1. 설치

1. 회사 구글 계정에서 **빈 구글 시트**를 새로 만듭니다.
2. 메뉴 **확장 프로그램 → Apps Script** 를 엽니다.
3. 왼쪽 파일 목록의 `Code.gs` 내용을 모두 지우고 `dist/Code.gs` 의 내용 전체를 붙여 넣습니다. 저장합니다.
   파일은 아래 주소에서 받을 수 있습니다 (이 브랜치가 main 에 합쳐진 뒤부터 열립니다).
   - `https://raw.githubusercontent.com/likelion-campus/PokeTokenBar/main/tools/usage-sheet/dist/Code.gs`
   - `https://raw.githubusercontent.com/likelion-campus/PokeTokenBar/main/tools/usage-sheet/appsscript.json`
4. 왼쪽 **프로젝트 설정(톱니바퀴)** 에서 **"appsscript.json" 매니페스트 파일 표시** 를 켭니다.
   편집기로 돌아가 `appsscript.json` 의 내용을 이 폴더의 `appsscript.json` 으로 바꾸고 저장합니다.
5. 위쪽 도구 모음의 함수 선택 칸(**실행** 과 **디버그** 단추 오른쪽의 드롭다운)을 열어 `setup` 을 고르고 **실행** 을 누릅니다. 권한 요청이 나오면 계정을 고르고 허용합니다
   ("확인되지 않은 앱" 경고는 **고급 → 이동** 으로 넘어갑니다). 한 번만 하면 됩니다.
   탭 14개(숨김 3개 포함)가 만들어지고 비어 있던 기본 탭(`시트1`)은 지워지며, 매시간 자동 새로 고침이 켜집니다.
   처음 실행이 느리거나 시트에 몇 해 치 기록이 쌓였다면 설계서 13장(한도와 규모, `docs/superpowers/specs/2026-11-16-usage-dashboard-design.md`)을 보세요.
6. **배포 → 새 배포 → 유형 선택(톱니바퀴) → 웹 앱** 을 고르고 아래처럼 설정합니다.
   - 실행: **나(Me)**
   - 액세스 권한: **모든 사용자(Anyone)**
7. **배포** 를 누르고 나오는 **웹 앱 URL** 을 복사해 개발자에게 전달합니다.

## 2. 나중에 스크립트를 고칠 때

새 `Code.gs` 를 붙여 넣고 저장한 뒤, `setup` 을 한 번 다시 실행합니다.
Enterprise 불러오기가 들어간 버전부터는 **외부 요청** 권한이 새로 필요해서, 권한 요청이 나오면 허용합니다.
그다음 **배포 → 배포 관리 → (연필) 편집 → 버전: 새 버전 → 배포** 를 합니다.

> **절대 "새 배포" 를 누르지 마세요.** 새 배포는 **새 URL** 을 만들고, 그러면 모든 팀원 앱이 시트에 닿지 못합니다.
> URL 을 유지하려면 반드시 "배포 관리 → 편집 → 새 버전" 입니다.

## 3. 탭 안내

| 탭 | 내용 |
|---|---|
| `이번 달`, `지난 7일`, `지난달` | 기간별 대시보드. 매시간 통째로 다시 쓰이니 **고치지 마세요**. |
| `플랜` | 지금 진행 중인 주의 한도 사용률, 이번 주 예상, 플랜 변경 제안. 대시보드처럼 매시간 다시 쓰이니 고치지 마세요. |
| `부서` | 팀 ID 별 부서 이름을 적는 곳. |
| `사람` | 사람 목록. 한 사람의 기기를 합칠 때 씁니다. |
| `설정` | 판정 기준 값. |
| `원본`, `한도` | 앱이 보낸 원본 기록. 고치지 마세요. |
| `엔터프라이즈 원본` | Anthropic 에서 불러온 사람별 하루 기록. 고치지 마세요. |
| `엔터프라이즈 사람` | Enterprise 멤버 목록. `부서` 칸을 직접 적는 곳입니다. |
| `팀이름`, `기기`, `엔터프라이즈기록` | 숨겨진 탭. 건드리지 마세요. (보는 법은 아래 "팀원이 안 보일 때") |

직접 고쳐도 되는 곳은 **`부서` 의 `부서이름`**, **`사람` 의 `합칠대상`**, **`설정` 의 값**, **`엔터프라이즈 사람` 의 `부서`** 뿐입니다.

## 4. 부서 이름 정하기

팀 ID 는 알아볼 수 없는 문자열이라, 앱이 보낸 팀 이름 중 가장 많은 것을 `참고팀이름` 칸에 적어 둡니다.
`참고팀이름` 을 보고 `부서이름` 칸에 부서 이름(예: 개발팀)을 적으세요. 같은 이름을 적은 팀 ID 는 한 부서로 합쳐 집니다.
`부서이름` 이 비어 있는 팀은 **미지정** 으로 남고 대시보드 합계에는 들어가지 않습니다.

## 5. 한 사람이 기기가 둘일 때

`사람` 탭에서 합칠 기기의 행을 찾아 `합칠대상` 칸에 **남길 기기의 memberId** 를 붙여 넣습니다.
그 기기의 사용량이 대상 사람에게 합산됩니다. 목록에 없는 ID 이거나 서로 가리키면 합치지 않고 그대로 둡니다.

## 6. 설정 값

`설정` 탭의 `값` 만 고칩니다. 바꾼 값은 **다음 새로 고침** 부터 적용됩니다. 잘못 적으면(빈 칸, 글자) 기본값으로 처리됩니다.

| 키 | 기본값 | 뜻 |
|---|---|---|
| `forecast_short_pct` | 100 | 리셋 때 예상이 이 % 이상이면 "모자람" |
| `forecast_fit_pct` | 70 | 이 % 이상이면 "알맞음", 아래는 "남음" |
| `full_week_pct` | 100 | 주간 최고 사용률이 이 % 이상이면 "다 쓴 주" |
| `suggest_weeks` | 4 | 제안에 쓰는 끝난 주간 창 수 |
| `suggest_up_full_weeks` | 2 | 그중 다 쓴 주가 이 수 이상이면 "올리기 검토" |
| `suggest_down_max_pct` | 40 | 모든 주의 최고 사용률이 이 % 미만이면 "내리기 검토" |
| `min_pace` | 0.1 | 창이 이 비율만큼 지나기 전에는 예상을 내지 않음 |
| `stale_hours` | 24 | 이보다 오래된 한도 값으로는 예상을 내지 않음 |
| `plan_order_claude` | Pro, Max, Ultra | 아래에서 위로 플랜 순서 |
| `plan_order_codex` | plus, pro | 아래에서 위로 플랜 순서 |

`plan_order_claude`, `plan_order_codex` 에는 `플랜` 탭의 **플랜 칸에 보이는 이름 그대로** 쉼표로 적어야 합니다
(대소문자는 구분하지 않습니다). 이름이 다르면 제안에 "→ 다음 플랜" 이 붙지 않습니다.

## 7. 팀원이 안 보일 때

기기를 다시 설치하거나 앱 데이터를 지우면 앱이 새 비밀값을 만들어, 같은 `memberId` 의 보고가 `device_mismatch` 로 거절될 수 있습니다.
이때는 숨겨진 `기기` 탭에서 그 팀원의 행을 지우면 다음 보고부터 다시 받습니다.
숨겨진 탭 보는 법: 시트 왼쪽 아래 **모든 시트(≡ 아이콘)** 를 열면 숨긴 탭이 나오고, 이름을 눌러 열 수 있습니다
(또는 메뉴 **보기 → 숨겨진 시트**).

## 8. Enterprise 멤버 불러오기

Claude Enterprise 조직의 멤버가 하루에 보낸 메시지와 Claude Code 세션 수를 Anthropic 관리자 통계에서 가져와,
세 대시보드의 팀 표 아래 **Enterprise** 줄에 보여 줍니다. 멤버는 아무것도 설치하지 않습니다.

**키 만들기.** 조직의 **Primary Owner** 만 만들 수 있습니다. claude.ai 에서 **조직 설정 → API** 로 가서
`read:analytics` 권한의 Analytics API 키를 만듭니다.

**키 넣기.** `setup` 을 실행한 **그 계정** 으로 시트를 열고, 메뉴 **사용량 대시보드 → Enterprise API 키 넣기** 에 붙여 넣습니다.
키는 그 계정에만 저장되고 시트 칸에는 쓰이지 않습니다. 넣으면 바로 한 번 불러옵니다. 첫 불러오기는 약 3개월 치라 몇 분 걸립니다.
키를 지우려면 **Enterprise API 키 지우기** 를 누릅니다. 이미 불러온 기록은 남습니다.

**부서 적기.** `엔터프라이즈 사람` 탭에 멤버가 자동으로 올라옵니다. `부서` 칸에 부서 이름을 적으세요.
비어 있으면 **미지정** 으로 남고 부서 표와 순위에는 들어가지 않습니다. 다시 불러와도 적어 둔 부서는 지워지지 않습니다.

**알아 둘 점**
- 데이터는 하루 늦게(보통 다음 날 밤 10시쯤) 채워집니다. 어제 치가 아직 없어도 오류가 아닙니다.
- 날짜는 UTC 하루 기준이라 한국 날짜와 9시간 어긋납니다.
- 메시지는 채팅 + Cowork 메시지입니다. Claude Code 는 세션 수로 따로 셉니다. **토큰은 아직 들어 있지 않습니다.**
- 관리자 통계에 안 나온 사람은 보이지 않습니다.

**상태 줄.** Enterprise 줄에 `마지막 불러옴 … · 데이터: … 까지` 가 보입니다. 불러오기가 실패하면 `· 오류: …` 가 붙습니다.
키가 없으면 `Enterprise 키가 없습니다` 라고 나옵니다. 키를 넣은 계정이 아닌 편집자는 키가 없어도 마지막 불러옴을 그대로 봅니다.
오류가 나도 대시보드의 다른 부분은 평소처럼 갱신됩니다.

## 9. 미리 보기

시트를 다시 열면 메뉴 **사용량 대시보드** 가 생깁니다.

- **샘플 데이터 넣기**: 가짜 부서 4개, 12명의 기록과 Enterprise 멤버 9명을 넣어 대시보드가 어떻게 보이는지 확인합니다.
- **샘플 데이터 지우기**: 샘플만 지웁니다 (Enterprise 샘플 포함). 진짜 기록은 그대로입니다. **실제로 쓰기 전에 꼭 지우세요.**
- **지금 새로 고침**: 기다리지 않고 바로 다시 계산합니다.

## 10. 공유

이 시트는 인사 담당자와 경영진에게 **뷰어** 권한으로만 공유합니다. 팀원에게는 시트 접근 권한을 주지 않습니다.
**편집자** 는 시트 주인만 합니다. 편집자는 Apps Script 프로젝트를 열어 볼 수 있기 때문입니다.
(팀원 앱은 웹 앱 URL 로만 기록을 보내고 시트를 열 수 없습니다.)

## 11. 알아 둘 점

- 데이터는 이 기능이 들어간 **앱 업데이트가 나온 뒤** 부터 쌓입니다. 그 업데이트는 Windows 포팅이 끝난 뒤에 나옵니다.
- 숫자는 실제 청구액이 아니라 **각자 기기의 로그에서 센 값** 입니다. 앱을 켜 둔 기기의 사용량만 잡힙니다.
- 앱이 없거나 팀 기능을 끈 사람은 아예 보이지 않습니다.

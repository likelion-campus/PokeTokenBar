# 팀 이름 동기화 설계 (팀용 포크)

- 작성일: 2026-11-23
- 상태: 방향은 사용자 승인("응 동기화되게 해줘, 시트에서 뭔가 손으로 수정하는 방향은 원치않아. 몇개의 팀이 생길지 확실하지도 않아 제어도 어렵고").
  새 팀의 이름을 입력받을지 기본값을 둘지는 사용자가 설계자에게 맡겼다("이름을 입력받게 하는게 좋은지, 아니면 기본값을 두는게 좋은지 판단해서 작업해줘").
- 저장소: `likelion-campus/PokeTokenBar`, 기준 `main` db19e93c (v2.5.639)
- 관련: #342 (사용량 시트가 기본 팀 이름을 거르는 투표 규칙), `2026-11-16-usage-dashboard-design.md`

표기 규칙: **[결정]** 은 사용자가 대화에서 직접 정한 것, **[설계자 판단]** 은 설계자가 사용자에게 설명했고 사용자가 반대하지 않은 것,
**[설계자 판단·미확인]** 은 사용자가 설계자에게 맡겨 설계자가 정한 것, **[구현자 재량]** 은 구현하면서 정해도 되는 것이다.

## 1. 의도와 이유

사용량 시트는 팀(방 코드)마다 앱이 보낸 팀 이름을 부서 이름으로 쓴다. 지금 팀 이름은 팀원마다 자기 앱에만 저장한 메모라서,
같은 방이어도 "팀 1", "AXP", "AXP Div"처럼 제각각이다. 그래서 2026-11-23 시트에서 한 팀이 통째로 미지정이 됐다(#342에서 시트 쪽 투표를 고쳐 막았다).

사용자는 시트에서 손으로 부서 이름을 채우는 방법을 원하지 않는다. 팀이 몇 개 생길지 모르고 관리하기 어렵기 때문이다 **[결정]**.
그래서 팀 이름을 방의 속성으로 바꾼다. 누가 바꾸든 같은 방 모두의 앱에서 같은 이름이 되고, 앱은 그 이름을 시트에 보낸다 **[결정]**.

## 2. 목표, 비목표, 반목표

목표
- 같은 방 코드의 팀원은 모두 같은 팀 이름을 본다(설정, 저장한 팀 목록, 팀 바꾸기 메뉴, 광장 창 제목).
- 사용량 보고의 `teamLabel` 이 그 공유 이름이 되어, 시트가 손 작업 없이 부서 이름을 얻는다.
- 새로 만든 팀은 처음부터 진짜 이름을 가진다.

비목표
- 시트 스크립트 변경. #342의 투표 규칙(바꾼 이름이 기본 이름을 이김)은 이전 버전 팀원이 섞인 동안의 안전망으로 그대로 둔다.
- 다른 네트워크에 있는 팀원과의 동기화. 이름은 광장 연결(같은 망)로만 오간다. 원격 광장은 보류된 기능이다.
- 이름을 바꾼 사람·시각 표시. 일정(코어타임·계절)과 달리 표시하지 않는다 **[설계자 판단·미확인]**.

반목표 (이렇게 되면 실패)
- 같은 방에서 이름이 끝내 하나로 모이지 않는다.
- 새 팀이 다시 "팀 1" 같은 기본 이름으로 시트에 쌓인다.
- 피어가 보낸 큰 값이나 이상한 값 하나가 저장되어 팀 전체의 presence 를 막는다.

## 3. 정한 것

### 3.1 새 팀은 이름을 입력해야 만들어진다 **[설계자 판단·미확인]**

"팀 만들기" 옆에 팀 이름 칸을 두고, 1~12자(닉네임 규칙 `validNickname`)를 넣어야 팀이 만들어진다. 칸은 비어 있고 미리 채운 기본값은 없다.
올바르지 않은 이름으로 누르면 코드 참여 실패와 같은 모양의 빨간 줄 "팀 이름은 1~12자로 입력해 주세요"가 뜨고 아무것도 만들지 않는다.

기본값을 두지 않는 이유:
- 2026-11-23 사고가 바로 기본값 때문이었다. 대부분의 팀원이 "팀 1"을 그대로 두었다. 미리 채운 값은 그대로 넘어가기 쉽다.
- "팀 N"은 목록 순서에서 나온 이름이라 방마다 겹치고 아무 뜻이 없다. 시트는 이런 이름을 미지정으로 본다.
- 팀을 만드는 사람은 그게 무슨 팀인지 안다. 팀마다 한 번, 한 칸이다.
- 닉네임 이름표 등 다른 곳에서 쓸 만한 기본값(예: "○○의 팀")은 부서 이름이 아니라서 시트에 잘못된 부서를 만든다.

### 3.2 참여할 때는 묻지 않는다 **[설계자 판단·미확인]**

코드로 참여하면 이름은 방에서 온다. 이름을 받기 전까지는 지금처럼 이 기기에만 있는 임시 이름 "팀 N"을 보여 주고, 이 임시 이름은 다른 팀원에게 보내지 않는다.
팀원을 처음 만나(광장 연결) 공유 이름을 받으면 그 이름으로 바뀐다. 받기 전에 직접 바꾸면 그 이름이 공유 이름이 된다.

### 3.3 누구나 바꾸고, 가장 나중에 바꾼 이름이 남는다 **[설계자 판단]**

코어타임·계절 설정(`PlazaSchedule`)과 같은 규칙이다.
- 이름에는 바꾼 시각(`changedAt`)과 바꾼 사람(`changedBy` = 멤버 ID)이 붙는다. 시각이 늦은 쪽이 이기고, 같으면 `changedBy` 가 큰 쪽이 이긴다.
- 내가 바꾸면 도장은 `max(지금, 가진 도장 + 0.001초)`다. 시계가 느린 기기에서 바꿔도 내가 가진 이름에 지지 않는다.
- 지금과 같은 이름으로 다시 저장하면 도장을 새로 찍지 않는다.
- 받은 이름은 이 조건을 모두 만족할 때만 저장한다: 지금 팀의 값이다(`settings.code == knownCode`, 일정과 같은 조건), 이름이 `validNickname(name) == name`,
  `changedBy` 가 UTF-8 64바이트 이하, `changedAt` 이 받는 기기 시각 + 600초 이하, 가진 도장보다 새롭다.
- 공유는 지금 들어가 있는 팀만 한다. 저장해 둔 다른 팀의 이름은 그 팀에 들어가 팀원을 만날 때 맞춰진다.

### 3.4 이미 있는 팀 **[설계자 판단]**

업데이트 뒤 처음 켤 때, 저장한 팀마다 도장이 없고 이름이 기본 이름(`^팀 [0-9]+$`, 시트의 `DEFAULT_TEAM_NAME` 과 같은 규칙)이 아니면,
그 이름에 아주 오래된 도장(`changedAt` = 1970-01-01 00:00:00 UTC, `changedBy` = 내 멤버 ID)을 찍어 공유 이름으로 삼는다. 기본 이름은 도장 없이 둔다.
- 그래서 누군가 바꿔 둔 이름이 있으면 그 방은 그 이름으로 모인다. 그런 이름이 여럿이면 `changedBy` 가 큰 쪽으로 모인다(누구 것이 될지는 정해져 있지 않다).
- 업데이트 뒤 누가 이름을 바꾸면 그 이름이 이긴다.
- 아무도 바꾸지 않은 옛 방은 "팀 N"으로 남는다. 누군가 설정에서 이름을 바꾸면 해결된다(설정의 안내 줄이 그걸 알려 준다).

### 3.5 이전 버전 팀원 **[설계자 판단]**

v2.5.639 이하는 새 필드를 모르고 무시한다. 그 팀원은 업데이트 전까지 자기 이름을 계속 보낸다. 그동안은 시트의 #342 투표가 메운다.
새 버전 팀원이 모두 같은 이름을 보내므로 대개 그 이름이 다수가 된다.

### 3.6 보이는 곳과 문구 **[설계자 판단·미확인]**

이름을 저장하는 곳은 지금처럼 `TeamSettings.SavedTeam.name` 하나다. 설정의 "팀 이름" 칸, 팀 바꾸기 메뉴, 저장한 팀 줄, 광장 창 제목, 사용량 보고가
모두 이 값을 읽으므로 공유 이름이 그대로 보인다. 화면 변경은 둘뿐이다.
- 팀이 없는 상태: "팀 만들기" 단추 앞에 팀 이름 칸(안내 글 "새 팀 이름")을 둔다. Enter 도 "팀 만들기"와 같다. 만들면 칸을 비운다.
- 팀이 있는 상태: "팀 이름" 줄 아래에 회색 안내 줄 "바꾸면 팀원 모두의 팀 이름이 바뀌어요"를 둔다.

맥과 윈도우는 같은 동작, 같은 문구다(윈도우는 맥을 따른다). 윈도우의 차이 목록(`docs/reference/windows-differences.md`)에 더할 것은 없다.

### 3.7 시트

바꿀 것이 없다. 앱의 사용량 기록(`UsageReportLedger.recordPresence`)은 그날·그 팀 항목의 이름을 가장 최근 이름으로 덮어쓰고,
이름이 들어간 날의 지문이 달라지므로 오늘 행이 다음 보고(대개 한 시간 안)에 다시 보내진다. 시트의 `팀이름` 탭은 팀원별로 받은 이름을 덮어쓴다.
지난날의 행은 그날의 이름을 그대로 둔다.

## 4. 동작 상세 (구현 기준)

데이터
- `TeamSettings.SavedTeam` 에 `nameChangedAt: Date?`, `nameChangedBy: String?` 를 더한다. 옛 저장값(이 키가 없음)도 그대로 읽힌다.
- 선 위의 값은 새 타입 `TeamNameStamp { name: String, changedAt: Date, changedBy: String }` (Codable, Equatable, Sendable)이고,
  `isNewer(than: TeamNameStamp?) -> Bool` 은 `PlazaSchedule.isNewer` 와 같은 규칙이다.
- `TeamSettings.teamNameStamp: TeamNameStamp?` 는 지금 팀의 항목에 도장이 있을 때만 값이 있다.

규칙(`TeamSettings`)
- `createTeam(code: TeamCode, named raw: String, now: Date) -> Bool`: 이름이 올바르지 않으면 false 이고 아무것도 바꾸지 않는다.
  올바르면 그 코드로 들어가고, 저장한 팀 항목의 이름을 그 이름으로, 도장을 (`now`, 내 멤버 ID)로 둔다.
- `renameCurrentTeam(_ raw: String, now: Date) -> Bool`: 지금처럼 올바르지 않으면 false. 이름이 달라질 때만 3.3의 도장을 찍는다.
- `adoptTeamName(_ s: TeamNameStamp, now: Date) -> Bool`: 3.3의 조건을 모두 만족하면 이름과 도장을 바꾸고 true.
- 3.4의 이전은 `init` 에서 멤버 ID가 정해진 뒤 한 번 한다. 이미 도장이 있으면 건드리지 않는다.
- `TeamSetup.create(_ nameDraft: String, into: TeamSettings, now: Date) -> Bool`: 새 코드를 만들어 `createTeam` 을 부른다. 맥과 윈도우가 함께 쓴다.

선(`TeamPresence`)
- `@LossyOptional var teamName: TeamNameStamp?` 를 더한다. 도장이 없으면 빠진다. 읽을 수 없는 값은 nil 이고 나머지 프레임은 그대로 읽힌다.
- `makePresence()` 는 `settings.code == knownCode` 일 때 `settings.teamNameStamp` 를 싣는다(일정과 같은 조건).
- presence 를 받으면 일정처럼 `adoptTeamName` 을 부르고, 일정이나 이름 중 하나라도 받아들였으면 presence 를 **한 번** 다시 보낸다.
- 내가 이름을 바꾸면 `applySettings` 가 바뀐 도장을 보고 presence 를 다시 보낸다(`sentSchedule` 과 같은 `sentTeamName`).
  `TeamRuntime.observeSettings` 가 도장을 관찰해야 이 경로가 돈다.

화면
- 맥 `TeamSettingsSection`, 윈도우 `WinTeamSection` 에 3.1과 3.6의 줄을 더한다. 맥은 `TeamSetup.create(..., now: Date())` 를,
  기존 이름 바꾸기 두 곳은 `renameCurrentTeam(draft, now: Date())` 를 부른다.
- 문구(`TeamLocalization`): `teamCreateNamePlaceholder` "새 팀 이름", `teamNameInvalid` "팀 이름은 1~12자로 입력해 주세요",
  `teamNameSharedCaption` "바꾸면 팀원 모두의 팀 이름이 바뀌어요".

## 5. 검증

- `TeamSettingsTests`: 만들기(올바른 이름, 빈 칸·공백·13자·개행), 참여 직후 도장 없음, 이름 바꾸기 도장(같은 이름은 그대로, 가진 도장이 미래여도 이김),
  받기(새 것, 옛 것, 같은 시각의 `changedBy` 비교, 600초 넘는 미래, 앞뒤 공백·13자, 65바이트 `changedBy`, 팀 없음, 도장 없는 항목), 옛 저장값 읽기와 이전(바꾼 이름만 오래된 도장, 다시 켜도 그대로, 새 이름이 이김).
- `TeamSessionTests`: presence 에 실림/빠짐, 받아서 저장하고 한 번 다시 보냄, 옛 값은 다시 보내지 않음, 내 이름 바꾸기가 다시 보냄, 코드가 막 바뀐 동안 받은 이름은 저장하지 않음.
- `TeamWireTests`: 필드가 없는 옛 프레임과 깨진 `teamName` 이 프레임을 망가뜨리지 않음.
- `TeamSetupTests`: `create` 올바른/올바르지 않은 이름.
- 윈도우 코드는 맥에서 빌드되지 않는다. 브랜치에서 윈도우 CI 를 한 번 돌려 확인한다.

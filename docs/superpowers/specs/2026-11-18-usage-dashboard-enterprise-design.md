# 사용량 대시보드 — Enterprise 멤버 불러오기 (추가 설계)

- 날짜: 2026-11-18
- 원 설계: `docs/superpowers/specs/2026-11-16-usage-dashboard-design.md` (이 문서는 그 위에 더한다. 겹치는 규칙은 원 설계를 따른다.)
- 표시: **[결정]** 사용자가 정함 · **[설계자 판단]** 설계자가 정함 · **[미확인]** 실제 키로 확인 전

## 1. 의도와 이유

- 회사 구성원 대부분은 Claude를 채팅으로만 쓴다(사용자, 2026-11-18). 채팅은 PC에 토큰 로그를 남기지 않아서,
  원 설계의 앱 수집(로그 읽기)은 Claude Code를 쓰는 사람만 잡는다.
- 회사의 결제 방식은 부서마다 다르다. Ultra는 대부분 개별결제이고, Max 사용자 중 일부는 Enterprise 조직에 속한다
  **[결정]**(사용자가 알려 준 사실).
- Enterprise 조직은 Anthropic의 공식 분석 API(Claude Enterprise Analytics API)가 사람별·하루별 활동을 준다.
  시트가 이 API를 직접 불러오면, 직원이 아무것도 설치하지 않아도 Enterprise 멤버의 채팅 사용이 잡힌다.
- 사용자가 승인한 범위 **[결정]**("응 그렇게해줘"):
  - 시트에 "Enterprise 불러오기"를 더한다. 하루 단위 데이터를 새 탭에 쌓는다.
  - 대시보드 세 탭(이번 달·지난 7일·지난달)에 Enterprise 멤버 섹션을 더한다. 많이 쓰는 사람, 적게 쓰는 사람, 부서별 합계를 보여 준다.
  - 키는 스크립트 안에 보관한다. 코드와 시트 칸에는 두지 않는다.
  - 키가 오기 전에 문서 기준으로 만들고 가짜 데이터로 시험한다. 키가 오면 실제 데이터로 확인한다.
  - 앱은 고치지 않는다. 그래서 윈도우 포팅과 상관없이 진행한다.

## 2. 목표 · 비목표 · 안티골

목표:
- Enterprise 멤버마다 하루별로 채팅 메시지, 대화, Cowork 메시지, Claude Code 세션을 시트에 쌓는다.
- 세 대시보드 탭에 Enterprise 섹션을 둔다. 타일, 부서 표, 많이·적게 쓰는 5명, 부서별 막대 차트 하나로 구성한다.
- 직원이 할 일은 없다. 시트 주인은 키를 한 번 넣고, 사람마다 부서를 한 번 적는다.

비목표 **[설계자 판단]**:
- 개별결제 채팅 사용자의 주간 사용률 수집(세션 키, 크롬 확장)은 다루지 않는다. 별도로 결정한다.
- PokeTokenBar 멤버(닉네임)와 Enterprise 멤버(이메일)를 한 사람으로 합치지 않는다. 섹션을 나눠 보여 준다.
- 플랜 탭은 바꾸지 않는다. Enterprise API에는 주간 사용률이 없다.
- **Enterprise 토큰 수는 이번에 넣지 않는다.** 토큰 엔드포인트(`/v1/organizations/analytics/usage`, 베타)는 사용량 과금형
  Enterprise에서만 의미가 있다. 좌석형이면 추가 크레딧만 보인다. 회사가 어느 쪽인지는 실제 키로만 확인된다. 키가 오고
  과금형으로 확인되면 그때 붙인다. 비용(금액)도 같은 이유로 뺀다.

안티골:
- 키가 코드, 시트 칸, 로그, 오류 문구, 저장소 중 어디든 남으면 실패다.
- Enterprise 불러오기가 실패해서 기존 대시보드 새로고침이 멈추면 실패다.
- 앱 보고(`doPost`)가 Enterprise 불러오기 때문에 기다리면 실패다.
- 시트 주인이 적은 부서를 불러오기가 덮어쓰면 실패다.

## 3. 불러오는 것

API 사실은 2026-11-18에 문서로 확인했다. 실제 응답 확인은 키가 온 뒤다 **[미확인]**.
- 문서: https://platform.claude.com/docs/en/manage-claude/analytics-api
- 문서: https://platform.claude.com/docs/en/api/beta/organization/analytics/users/list

요청:
- `GET https://api.anthropic.com/v1/organizations/analytics/users?date=YYYY-MM-DD&limit=1000`. 다음 쪽이 있으면 `page=<next_page>`를 붙인다.
- 헤더는 `x-api-key: <키>` 와 `anthropic-version: 2026-10-21` 이다.
- 날짜는 UTC 하루다. 2026-01-01 이후만 있다.
- 응답은 `{ "data": [...], "next_page": <문자열 또는 null> }` 이다.

사람 한 명·하루 한 행으로 저장하는 값 **[설계자 판단]**:
- `user.id`, `user.email_address`. 이 엔드포인트에는 이름이 없다.
- **채팅 메시지** = `chat_metrics.message_count` + `chat_cowork_unified_metrics.chat.message_count`.
- **대화** = `chat_metrics.distinct_conversation_count` + `chat_cowork_unified_metrics.chat.distinct_conversation_count`.
- **Cowork 메시지** = `cowork_metrics.message_count` + `chat_cowork_unified_metrics.sessions.message_count`.
- **Claude Code 세션** = `claude_code_metrics.core_metrics.distinct_session_count`.
- 더하는 이유: 통합(Chat and Cowork unified) 기능을 켠 사람은 그날부터 숫자가 통합 칸으로 옮겨 간다. 둘을 더해야 전후가 이어진다.
- `null` 과 칸이 없는 경우는 0으로 센다. 통합 칸은 그 기능이 없는 조직에선 아예 빠진다.
- `user` 가 `null` 인 행(묶음 행)은 버린다.

대시보드의 "메시지" = 채팅 메시지 + Cowork 메시지 **[설계자 판단]**. 많이·적게 쓰는 사람 순위의 기준이다.
Claude Code 사용은 세션 수로 따로 보여 준다. Claude Code를 주로 쓰는 사람의 토큰은 원래 앱 섹션이 센다.

## 4. 탭

- **엔터프라이즈 원본**(보임): 날짜(UTC), userId, 이메일, 채팅 메시지, 대화, Cowork 메시지, Claude Code 세션, 받은 시각.
  날짜+userId 마다 한 행이다. 같은 날을 다시 불러오면 덮어쓴다.
- **엔터프라이즈 사람**(보임): userId, 이메일, 부서, 처음 본 날.
  - 불러오기가 새 사람을 자동으로 더하고, 바뀐 이메일을 고친다. **부서 칸은 시트 주인만 쓴다.**
  - 부서가 비면 "미지정"이다. 합계에서 빠지고, 메모 줄에 사람 수와 메시지 수만 보인다. 원 설계 5장의 미지정 규칙과 같다.
  - 부서 이름은 자유롭게 적는다. 앱 섹션의 부서 이름과 같게 적으면 보기 좋지만 서로 묶지는 않는다 **[설계자 판단]**.
- **엔터프라이즈기록**(숨김): 날짜, 불러온 시각, 행 수. 이미 불러온 날을 기억한다. 활동이 0명인 날도 다시 부르지 않게 하려는 것이다.

## 5. 불러오는 때와 실패

- 매시간 새로고침(`refreshAll`)이 대시보드를 그리기 전에 불러온다. 별도 트리거를 만들지 않는다 **[설계자 판단]**.
- 메뉴의 "지금 새로 고침"도 같은 길을 탄다.
- 불러올 날 **[설계자 판단]**:
  - 범위는 "지난달" 탭의 비교 기간 첫날(지지난달 1일)부터 어제(UTC)까지다.
  - 그 범위에서 아직 안 불러온 날과, 최근 3일(어제 UTC − 2일 ~ 어제)을 불러온다.
  - 최근 3일을 다시 부르는 이유: 문서상 숫자가 며칠 동안 몇 % 바뀔 수 있다.
  - 오래된 날부터 차례로 부른다.
- 아직 준비 안 된 날은 400 오류를 받는다. 데이터는 보통 다음 날 13:00~13:30 UTC에 준비된다.
  - 최근 3일 안의 날이 400이면 정상으로 보고 거기서 멈춘다. 다음 시간에 다시 부른다.
  - 그보다 오래된 날이 400이면 오류로 기록한다.
- 한 번에 최대 100번 요청한다. 요청 사이에 1초 쉰다. 조직당 분당 60번 제한 안에 들고, 처음 채우는 날 수(최대 약 95일)도 한 번에 들어간다.
  - 429(요청이 너무 많음)를 받으면 이번 회차를 멈추고 다음 시간에 잇는다.
- 401·403(키 문제)이나 그 밖의 오류는 이번 회차를 멈추고 상태에 적는다. 대시보드는 이미 쌓인 데이터로 그대로 새로 고친다.
  오류가 대시보드 새로고침을 막지 않는다.
- 상태(마지막 성공 시각, 가장 최근 날, 마지막 오류의 짧은 문구)는 각 대시보드의 Enterprise 섹션 첫 줄에 보인다.
  오류 문구에는 상태 코드와 API의 `error.type`·`error.message` 만 넣는다. 요청 주소나 헤더는 넣지 않는다.
- 잠금 **[설계자 판단]**:
  - 네트워크 요청은 잠금 없이 보낸다.
  - Enterprise 탭에 쓸 때만 스크립트 잠금을 잡는다. 샘플 넣기·지우기와 겹치지 않게 하려는 것이다.
  - `refreshAll` 은 지금처럼 문서 잠금 안에서 돈다.
  - 앱 보고(`doPost`)는 Enterprise 탭을 건드리지 않는다. 쓰기 하나가 짧아서 잠금을 오래 잡지 않는다.

## 6. 키

- 메뉴 "Enterprise API 키 넣기"가 입력 창을 띄운다. 입력한 값은 **사용자 속성(UserProperties)** 에 저장한다 **[설계자 판단]**.
  - 스크립트 속성이 아닌 이유: 스크립트 속성은 시트 편집자 누구나 편집기에서 볼 수 있다.
    사용자 속성은 넣은 사람으로 실행될 때만 읽힌다.
  - 그래서 키는 `setup` 을 실행한 사람, 곧 매시간 트리거의 주인이 넣어야 한다. 다른 편집자가 "지금 새로 고침"을 누르면
    그 회차는 키가 없어 불러오기를 건너뛴다. 대시보드는 그대로 새로 고친다.
- 키를 넣은 뒤 바로 한 번 불러오고 결과를 알림 창으로 보여 준다.
- 메뉴 "Enterprise API 키 지우기"가 지운다.
- 키는 Enterprise 조직의 Primary Owner만 만들 수 있다. 만드는 곳은 claude.ai > 조직 설정 > API이고, 범위는 `read:analytics` 다.
- 시트 공유 규칙: 인사팀·임원은 보기 권한만 받는다. 편집 권한은 주인만 가진다. README에 적는다.

## 7. 대시보드 섹션

세 대시보드 탭 모두, 기존 내용 아래에 같은 모양으로 둔다. 각 탭의 기간(이번 달·지난 7일·지난달)과 비교 기간을 그대로 쓴다.
API 날짜는 UTC 날짜지만 기간 비교에는 그대로 쓴다 **[설계자 판단]**. 한국 날짜와 9시간 어긋나는 것은 메모에 적는다.

- 제목: "Enterprise 멤버 (Claude 관리자 통계)"
- 상태 줄. 둘 중 하나다:
  - "마지막 불러옴: yyyy-MM-dd HH:mm · 데이터: yyyy-MM-dd까지"
  - "Enterprise 키가 없습니다 — 메뉴 > Enterprise API 키 넣기"
  - 마지막 오류가 있으면 줄 끝에 붙인다.
- 키도 없고 그 기간에 데이터도 없으면 제목과 상태 줄만 보인다.
- 타일: 메시지 · 1인 평균 · 쓰는 사람 · 부서 수. 그 아래 줄에 기존 섹션처럼 이전 기간 대비 변화를 둔다.
- 부서 표(A:D): 부서 · 메시지 · 1인 평균 · 인원. 메시지가 많은 순이다.
- 많이 쓰는 5명, 적게 쓰는 5명(F:I): 이름 · 부서 · 메시지 · Claude Code 세션.
  - 이름은 이메일의 @ 앞부분이다. 이 API에는 이름이 없다.
  - 적게 쓰는 표에는 많이 쓰는 표에 든 사람을 다시 넣지 않는다. 기존 섹션과 같은 규칙이다.
- "쓰는 사람"은 그 기간에 한 행이라도 있는 사람이다. 메시지가 0이어도 센다. 그래야 좌석은 있는데 안 쓰는 사람이
  "적게 쓰는 사람"에 0으로 나온다.
  - API가 활동 없는 사람을 아예 안 보내는지는 문서에 없다 **[미확인]**. 안 보내면 그런 사람은 안 보인다. 메모에 적는다.
- 차트: "부서별 메시지 (Enterprise)" 막대 하나를 J열에 둔다. 기존 차트와 같은 크기다.
- 메모:
  - "Enterprise 조직 멤버만, Anthropic 관리자 통계 기준입니다. 하루 늦게(보통 다음 날 밤 10시쯤) 채워집니다."
  - "날짜는 UTC 하루 기준이라 한국 날짜와 9시간 어긋납니다."
  - "메시지 = 채팅 + Cowork 메시지. Claude Code 사용은 세션 수로 따로 셉니다."
  - "부서는 엔터프라이즈 사람 탭에서 정합니다. 비어 있으면 미지정입니다."
  - "관리자 통계에 안 나온 사람은 보이지 않습니다."

## 8. 샘플 데이터

- "샘플 데이터 넣기"는 가짜 Enterprise 멤버도 넣는다. 기존 샘플 부서 이름으로 여러 명을 넣고, 부서가 빈 사람도 한 명 둔다.
  표시는 `user_sample_` 로 시작하는 userId와 `sample-…@sample.example` 이메일이다.
- "샘플 데이터 지우기"는 이 행들도 지운다. 엔터프라이즈기록 탭은 샘플이 쓰지 않는다.

## 9. 이번에 함께 고치는 것

설치 확인(2026-11-16)과 규모 검토(2026-11-17)에서 나온 것이다. 같은 스크립트 업데이트에 싣는다 **[설계자 판단]**.
- 차트의 머리글이 빈 첫 막대("부서")로 보이는 문제. 모든 차트에 머리글 한 줄을 지정한다(`setNumHeaders(1)`).
- 데이터 탭의 빈 열 정리. 새 탭은 기본 26열로 생긴다. 시트의 1천만 칸 한도는 빈 칸도 센다.
  `setup` 이 데이터 탭의 쓰지 않는 열을 지운다. 그 열에 내용이 하나라도 있으면 건드리지 않는다.
- 샘플 데이터에서 플랜 제안이 "올리기 검토"와 "내리기 검토"도 나오게 한다. 지금은 유지만 나와서 미리 보기로 확인할 수 없다.

## 10. 업데이트 방법 (시트 주인)

- 새 `dist/Code.gs` 를 붙여 넣고 저장한다. `setup` 을 한 번 실행한다. 새 탭이 생기고 빈 열이 정리된다.
- **배포 관리 → 편집 → 새 버전**으로 올린다. 웹 앱 주소는 그대로다. 새 배포는 만들지 않는다.
- 새 기능이 외부 주소(`api.anthropic.com`)를 부르므로 권한 승인 창이 한 번 더 뜬다.
- 키를 받으면 메뉴 > Enterprise API 키 넣기.

## 11. 키가 와야 확인되는 것 [미확인]

- 실제 응답 모양과 `next_page` 동작.
- 준비 안 된 날의 400 문구. 이 설계는 문구를 읽지 않고 날짜만으로 판단한다.
- 활동 없는 사람이 `data` 에 나오는지.
- 회사 조직이 사용량 과금형인지. 과금형이면 토큰을 붙인다(비목표 참고).

## 12. 구현자 재량

- 탭 열 순서, 내부 함수 이름.
- 상태(5장)는 **문서 속성(DocumentProperties)** 에 둔다 **[설계자 판단]**. 키가 없는 편집자가 새로 고쳐도 주인의 마지막
  불러오기 상태가 보여야 하기 때문이다. 상태에는 비밀값이 없다.
- 섹션의 정확한 행 위치(기존 내용 아래, 차트·표가 겹치지 않으면 된다).
- 가짜 API 응답 픽스처의 모양. 단, 문서 예시의 필드 이름을 그대로 쓴다.

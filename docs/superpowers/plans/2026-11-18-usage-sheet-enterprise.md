# Usage Sheet — Enterprise Members Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pull each Claude Enterprise member's daily activity from Anthropic's Enterprise Analytics API into the usage sheet. Show it as a new section on the three period dashboards, with no install for employees. The same script update also fixes three issues from the first install.

**Architecture:** This extends `tools/usage-sheet/` (merged in #229).
- A new module `src/35_enterprise.js` holds the API client, the pure record parser, the day picker, the writer and the reader.
- A new module `src/37_enterprise_dashboard.js` holds the pure section model and its renderer.
- `refreshAll` pulls before it renders. A pull failure is recorded and never stops the refresh.
- The API key lives in the owner's `UserProperties`. The pull status lives in `DocumentProperties`, which holds no secret.
- Tests use the same vm harness with new strict fakes: `UrlFetchApp`, `PropertiesService`, `Utilities.sleep`, Ui prompt/alert, a column-bounded grid and a chart builder that requires a header count.

**Tech Stack:** Apps Script (V8), Node ≥ 20 built-ins only (`node:test`, `node:assert/strict`, `node:vm`).

**Spec:** `docs/superpowers/specs/2026-11-18-usage-dashboard-enterprise-design.md` (Korean, the binding authority for this plan). It builds on `docs/superpowers/specs/2026-11-16-usage-dashboard-design.md`.

## Global Constraints

- **Scope:** only `tools/usage-sheet/`, this plan, and the spec. No Swift, no app changes. Never run `swift build` or `swift test`.
- **Dependencies:** none. Node built-ins only.
- **Shipping:**
  - `dist/Code.gs` is generated by `node tools/usage-sheet/build.js` and committed.
  - Every task rebuilds it before committing, because `test/build.test.js` fails on a stale dist.
  - Never edit dist by hand.
- **Tests:** `node --test tools/usage-sheet/test/` runs everything. No real network. The `UrlFetchApp` fake is the only HTTP.
- **Language:** sheet-facing text (tab names, headers, labels, menu, alerts, README) is Korean. Identifiers, comments and commits are English. Commits use Conventional Commits and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Secrets:** the API key may appear only in the `x-api-key` request header and in `UserProperties` under `ENT_KEY_PROP`. Never in a sheet cell, a status string, `DocumentProperties`, an exception message, a URL, or a log.
- **Free text:** every string from the API goes through `asText` / `asTextRows` before it is written, the same as peer text today.
- **Workspace:** `.worktrees/usage-enterprise`, branch `feat/usage-sheet-enterprise`. Never use bare `git stash`.

`TAB_SPECS` gains three entries, appended after 설정 in this order:
- `{ name: TAB_ENT_RAW, cols: COLS_ENT_RAW, textCols: [1] }`
- `{ name: TAB_ENT_PEOPLE, cols: COLS_ENT_PEOPLE, textCols: [4] }`
- `{ name: TAB_ENT_LOG, cols: COLS_ENT_LOG, textCols: [1], hidden: true }`

Request, per page:
- URL: `ENT_API_URL + "?date=" + date + "&limit=" + ENT_PAGE_LIMIT`, plus `"&page=" + encodeURIComponent(nextPage)` after the first page.
- Options: `{ method: "get", headers: { "x-api-key": key, "anthropic-version": ENT_API_VERSION }, muteHttpExceptions: true }`.

Record → row (spec 3장):
- Missing objects and `null` values count as 0.
- A record whose `user` is null, or has no `user.id`, is dropped.
- The row is `[date, user.id, user.email_address || "", chat, conv, coworkMsg, codeSessions, nowIso]`:
  - `chat = chat_metrics.message_count + chat_cowork_unified_metrics.chat.message_count`
  - `conv = chat_metrics.distinct_conversation_count + chat_cowork_unified_metrics.chat.distinct_conversation_count`
  - `coworkMsg = cowork_metrics.message_count + chat_cowork_unified_metrics.sessions.message_count`
  - `codeSessions = claude_code_metrics.core_metrics.distinct_session_count`

Status (`DocumentProperties[ENT_STATUS_PROP]`) is JSON `{ "lastRunMs": number|null, "newestDate": "yyyy-MM-dd"|null, "error": string|null }`.
- A run that ends without error sets `lastRunMs = nowMs`, `error = null`, and `newestDate` to the newest date in 엔터프라이즈기록.
- A run that ends with an error keeps `lastRunMs`, sets `error`, and refreshes `newestDate`.
- A user with no key never touches the status.
- `error` text:
  - HTTP failure: `code + " " + body.error.type + ": " + body.error.message`. When the body is not that shape, `code + " 응답"`.
  - Thrown fetch: `"요청 실패: " + e.message`.
  - Unparseable 200: `"응답을 읽지 못했습니다"`.
  - Every form is cut to 200 characters.

Status line (spec 7장), first match wins:
1. No status and the running user has no key → `"Enterprise 키가 없습니다 — 메뉴 > Enterprise API 키 넣기"`.
2. `lastRunMs` set → `"마지막 불러옴: " + formatDate(lastRunMs, tz, "yyyy-MM-dd HH:mm") + " · 데이터: " + (newestDate || "없음") + "까지"`.
3. Otherwise → `"아직 불러오지 못했습니다"`.

When `error` is set, append `" · 오류: " + error`.

Menu, in this order:
- `지금 새로 고침`
- `샘플 데이터 넣기`
- `샘플 데이터 지우기`
- `Enterprise API 키 넣기` → `setEnterpriseKey`
- `Enterprise API 키 지우기` → `clearEnterpriseKey`

Section notes, verbatim, one per row:
- `Enterprise 조직 멤버만, Anthropic 관리자 통계 기준입니다. 하루 늦게(보통 다음 날 밤 10시쯤) 채워집니다.`
- `날짜는 UTC 하루 기준이라 한국 날짜와 9시간 어긋납니다.`
- `메시지 = 채팅 + Cowork 메시지. Claude Code 사용은 세션 수로 따로 셉니다.`
- `부서는 엔터프라이즈 사람 탭에서 정합니다. 비어 있으면 미지정입니다.`
- `관리자 통계에 안 나온 사람은 보이지 않습니다.`

## Rulings already made (do not reopen)

- **Stale rows on a re-fetched day are left alone.** If a re-fetch returns fewer users for a day, the missing users' old rows stay. Revisions are "a few percent" of values. The API does not document users dropping out. If this proves wrong it costs one stale row per dropped user.
- **The status lives in DocumentProperties.** An editor without the key must still see the owner's last pull (Review Focus 4).
- **Section people:** "쓰는 사람" counts users with at least one row in the period, even with 0 messages.
  - Top and bottom lists and the tiles count department-assigned users only. Unassigned users appear only in the 미지정 line.
  - This mirrors `summarizePeriod`.

## Review Focus

1. The owner types a 부서 for a member, then the next pull re-fetches that member's days. The 부서 must survive, so the people upsert rewrites column B only. The test lives in Task 1.
2. The newest days return 400 every hour before the API has them. That is normal. The status must show no error, and the run stops there (Task 1).
3. A member switches to Chat and Cowork unified mid-period, so the messages move to `chat_cowork_unified_metrics`. The totals must stay continuous (Task 1 parser, Task 2 totals).
4. An editor without the key presses 지금 새로 고침 after the owner's pull. The line must show the owner's `마지막 불러옴`, not `키가 없습니다`, and no request is sent (Task 2).
5. The first pull backfills about 95 days with a 1 s sleep between requests. A 429 after 40 days keeps those 40 days. The next run resumes at day 41 without re-fetching the saved old days (Task 1).

**Interfaces (produced):**
- `utcDateString(ms) -> "yyyy-MM-dd"` (UTC day of `ms`).
- `entRecordToRow(rec, date, nowIso) -> Array | null`.
- `entDaysToFetch(fetched: Set<string>, first: string, yesterday: string, recentDays: number) -> string[]`
  - Ascending.
  - Includes every day in [first, yesterday] that is not in `fetched`, plus every day in [yesterday − recentDays + 1, yesterday].
  - Empty when `first > yesterday`.
- `entFetchDay(key, date, budget: {left:number, sent:number}) -> { kind: "ok", records } | { kind: "http", code, body } | { kind: "budget" } | { kind: "bad_json" }`
  - Follows `next_page` until null.
  - Every request decrements `budget.left`. It returns `budget` before sending when `left` is 0.
  - It calls `Utilities.sleep(ENT_SLEEP_MS)` before every request except the run's first, so `budget.sent > 0` means sleep.
  - A thrown `UrlFetchApp.fetch` propagates.
- `pullEnterprise(ss, nowMs, tz) -> { skipped: true } | { saved: number, error: string|null }`
  - Reads the key, picks the days and fetches with no lock held.
  - Then writes all collected days under `withScriptLock`, then writes the status.
  - `first = max(periodRange("lastMonth", localDateString(nowMs, tz)).prevStart, ENT_FIRST_DATE)`.
  - `yesterday = utcDateString(nowMs − DAY_MS)`.
  - A 400 for a day ≥ yesterday − (ENT_RECENT_DAYS − 1) stops the run without error. Any other non-200 stops it with error.
  - `budget` and `bad_json` stop the run. `bad_json` is an error, `budget` is not.
  - A thrown fetch is caught here. It becomes the `"요청 실패: "` error, and the days already collected are still written.
- `readEnterprise(ss, tz) -> { usage: [{date, userId, email, chat, conv, cowork, code}], people: null-proto map userId -> {email, dept}, status: object|null, hasKey: boolean }`.
- The writer, inside the lock:
  - Upserts 엔터프라이즈 원본 keyed by `date|userId`.
  - Upserts 엔터프라이즈 사람 keyed by userId. A new row is `[userId, email, "", today-local]`. An existing row rewrites only column B (email) via `upsertRows` `spans: [[2, 1]]`.
  - Upserts 엔터프라이즈기록 keyed by date: `[date, nowIso, rowCount]`.
- `withScriptLock` is in `50_admin.js`. Function declarations hoist across the concatenated file, so it is callable.

**Harness additions:**
- `UrlFetchApp.fetch(url, opts)`:
  - Answers from `fakes.http.handler(url, opts)`, which tests set. A handler returns `{ code, body }`, where `body` is an object or a raw string.
  - It records `{url, opts}` in `fakes.http.requests`.
  - Like Apps Script, it throws on a code ≥ 400 unless `opts.muteHttpExceptions` is true.
  - Its response has `getResponseCode()` and `getContentText()`.
- `PropertiesService.getUserProperties()` and `PropertiesService.getDocumentProperties()`: separate in-memory stores with `getProperty`, `setProperty` and `deleteProperty`. Tests can reach them as `fakes.props.user` and `fakes.props.doc`.
- `Utilities.sleep(ms)` records into `fakes.sleeps`.
- Document every addition in the harness header comment, the way existing fakes are documented.

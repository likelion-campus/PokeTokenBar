# Usage Sheet (sheet side) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Google Sheet side of the team usage dashboard: an Apps Script web app that accepts the app's usage and weekly-limit reports, a one-call sheet setup, three period dashboards, a plan tab, sample data, and an install guide. The sheet owner can deploy it before any app change exists.

**Architecture:** Plain JavaScript in `tools/usage-sheet/src/*.js`, concatenated in name order into one file, `dist/Code.gs`, which the owner pastes into Apps Script.
- All logic that can be pure is pure: validation, merge planning, dashboard and plan computation.
- Thin glue calls `SpreadsheetApp` and the other Apps Script services.
- Node tests run the concatenated source in a `vm` context with in-memory fakes of the Apps Script services they use. The code under test is therefore byte-identical to what ships.
- Dashboards are computed by script, not by sheet formulas. An hourly trigger and a menu item write the values, and the charts are rebuilt on each refresh.

**Tech Stack:** Apps Script (V8 runtime), Node ≥ 20 built-ins only (`node:test`, `node:assert/strict`, `node:vm`, `node:fs`, `node:path`, `node:crypto`).

**Spec:** `docs/superpowers/specs/2026-11-16-usage-dashboard-design.md` (Korean). Sections 3, 4, 4.1, 5, 7, 8, 9, 9.1 and 13 apply. Sections about the app (6, 10, 11) are out of scope here, except for the wire contract the app will follow.

## Global Constraints

- **Scope:** no Swift or app changes. Do not run `swift build` or `swift test`, because the Windows port needs this Mac's only build slot. TEAM.md is not touched in this plan.
- **Dependencies:** none. No `package.json`, no npm. Node built-ins only.
- **Shipping:** what ships is `tools/usage-sheet/dist/Code.gs` plus `tools/usage-sheet/appsscript.json`. `dist/Code.gs` is generated by `node tools/usage-sheet/build.js` and committed. Never edit it by hand.
- **Tests:** `node --test tools/usage-sheet/test/` runs every test. No real network and no real Google calls.
- **Language:** sheet-facing text (tab names, headers, labels, menu, README) is Korean. Code identifiers, comments, CONTRACT.md and commits are English. Commits use Conventional Commits and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Shared token:** `SHARED_TOKEN = "996c41db62671eaf62a86cf3e18202ee"`. It is public by design (spec 7장): it only turns away passing scanners.
- **Device secret:** the script never stores a device secret, only its SHA-256 hex.
- **Workspace:** work only in `.worktrees/usage-dashboard` (branch `feat/usage-dashboard`).
- **Stash:** never use bare `git stash`.

## Wire contract v1 (Task 1 writes it into CONTRACT.md; every task uses these names)

```json
{
  "v": 1,
  "token": "996c41db62671eaf62a86cf3e18202ee",
  "member": { "id": "8F1C…-UUID", "secret": "base64url-or-hex, 32–128 chars",
              "nickname": "지아", "appVersion": "2.5.640", "platform": "mac" },
  "days": [
    { "date": "2026-11-16", "team": "t_ab12cd34ef56", "teamLabel": "팀 1",
      "tools": [ { "tool": "claude_code", "input": 1200, "output": 800,
                   "cacheWrite": 5000, "cacheRead": 90000 } ] }
  ],
  "limits": [
    { "tool": "claude", "account": "e_3f9a…", "domain": "likelion.net", "plan": "Max",
      "usedPercent": 82.5, "resetsAt": "2026-11-19T09:00:00Z",
      "readAt": "2026-11-16T10:00:00Z", "team": "t_ab12cd34ef56" }
  ]
}
```

**Envelope.** A failure here rejects the whole request with `{ok:false, error}`.

| Field | Rule | Error code |
|---|---|---|
| body | ≤ 262144 bytes (UTF-8) | `too_large` |
| JSON | must parse to an object | `bad_json` |
| `v` | must be `1` | `bad_version` |
| `token` | must equal `SHARED_TOKEN` | `bad_token` |
| `member.id` | matches `/^[0-9A-Fa-f]{8}-[0-9A-Fa-f]{4}-[0-9A-Fa-f]{4}-[0-9A-Fa-f]{4}-[0-9A-Fa-f]{12}$/` | `bad_member` |
| `member.secret` | matches `/^[A-Za-z0-9_-]{32,128}$/` | `bad_member` |
| `member.nickname` | after trimming, 1–12 characters, no newline (the app's `validNickname`) | `bad_member` |
| `member.appVersion` | matches `/^[0-9A-Za-z.+-]{1,32}$/` | `bad_member` |
| `member.platform` | one of `mac`, `windows` | `bad_member` |
| `days` | an array of at most 62 entries | `too_many_rows` |
| `limits` | an array of at most 16 entries; omitted means `[]` | `too_many_rows` |
| tools | a day holds at most 32 | `too_many_rows` |

**Rows.** An invalid day, tool or limit entry is dropped and counted in `dropped`. The rest of the request still goes through.

- **`date`**
  - Must match `/^\d{4}-\d{2}-\d{2}$/` and be a real calendar date.
  - It must lie between today − 400 days and today + 1 day, in the script's time zone.
- **`team`:** must match `/^[A-Za-z0-9_-]{4,64}$/`.
- **`teamLabel`:** optional. When present it follows the nickname rule; an invalid label becomes `""` and does not drop the day.
- **`tools`**
  - Each `tool` id must match `/^[a-z0-9_.-]{1,32}$/`.
  - Each of the four counts must be an integer `Number.isSafeInteger(n)` with `0 ≤ n ≤ 1e13`.
  - An invalid tool entry is dropped on its own.
  - A day with `tools: []` is valid. It records a zero row with tool `-`, so that a member with no usage still appears (spec 4장 "사용량이 0인 날").
  - A day whose non-empty `tools` list loses every entry is dropped too (one more in `dropped`). It never turns into a `-` row.
- **Duplicates:** a repeated `date|tool` within one payload keeps the last occurrence.
- **Limit fields**
  - `tool` uses the tool rule.
  - `account` must match `/^[A-Za-z0-9_-]{4,128}$/`.
  - `domain` is `""` or matches `/^[a-z0-9.-]{1,253}$/`; it is lowercased first.
  - `plan` is 1–40 characters.
  - `usedPercent` is finite and between 0 and 1000.
- **Limit times**
  - `resetsAt` and `readAt` must parse with `Date.parse`.
  - `resetsAt` must lie within now ± 8 days.
  - `readAt` must lie between now − 8 days and now + 10 minutes.
  - `resetsAt` is normalized to the nearest whole hour UTC (ISO string, `…:00:00.000Z`), because the source jitters by seconds.
- **App obligations** (documented in CONTRACT.md, not checked by the script):
  - When the email is known, `account` is `"e_"` plus the first 16 hex characters of the SHA-256 of the lowercased email. Otherwise it is `"m_" + member.id + "_" + localAccountId`.
  - `team` is the app's one-way team ID (spec 5장).

**Response.** The response is always HTTP 200 JSON:
- success: `{"ok":true,"accepted":{"days":<rows written>,"limits":<rows written>},"dropped":<n>}`;
- failure: `{"ok":false,"error":"<code>"}`.

`device_mismatch` is the error code when a known `member.id` arrives with a different secret.

## Sheet schema (Task 2 creates it; Tasks 3–5 read it)

Tab names and headers are exact. Row 1 is the header. `@` means the column has the plain-text number format.

| Tab (const) | Columns |
|---|---|
| `원본` (`TAB_RAW`) | memberId, 닉네임, 날짜@, 도구, 팀ID, 입력, 출력, 캐시쓰기, 캐시읽기, 합계, 앱버전, 플랫폼, 받은시각 |
| `한도` (`TAB_LIMITS`) | 계정, 도구, 리셋시각@, memberId, 팀ID, 플랜, 이메일도메인, 최고사용률, 마지막사용률, 마지막읽은시각@ |
| `사람` (`TAB_PEOPLE`) | memberId, 닉네임, 마지막받은시각, 합칠대상, 앱버전, 플랫폼 |
| `부서` (`TAB_DEPTS`) | 팀ID, 부서이름, 참고팀이름, 처음본날@ |
| `팀이름` (`TAB_TEAMLABELS`, hidden) | 팀ID, memberId, 팀이름, 마지막받은시각 |
| `기기` (`TAB_DEVICES`, hidden) | memberId, 비밀값해시, 처음본시각, 마지막본시각 |
| `설정` (`TAB_SETTINGS`) | 키, 값, 설명 |
| `이번 달`, `지난 7일`, `지난달` | dashboard tabs (Task 3) |
| `플랜` | plan tab (Task 4) |

- **Row keys.** The raw-tab key is `memberId|날짜|도구`. The limits-tab key is `계정|도구|리셋시각`.
- **Owner-edited columns.** Only `부서이름` (부서) and `합칠대상` (사람) are edited by the owner. Upserts never overwrite them.
- **Settings defaults.** Values are as written: key, value, description.
  - `forecast_short_pct`: 100. 리셋 때 예상이 이 % 이상이면 "모자람".
  - `forecast_fit_pct`: 70. 이 % 이상이면 "알맞음", 아래는 "남음".
  - `full_week_pct`: 100. 주간 최고 사용률이 이 % 이상이면 "다 쓴 주".
  - `suggest_weeks`: 4. 제안에 쓰는 끝난 주간 창 수.
  - `suggest_up_full_weeks`: 2. 그중 다 쓴 주가 이 수 이상이면 "올리기 검토".
  - `suggest_down_max_pct`: 40. 모든 주의 최고 사용률이 이 % 미만이면 "내리기 검토".
  - `min_pace`: 0.1. 창이 이 비율만큼 지나기 전에는 예상을 내지 않음.
  - `stale_hours`: 24. 이보다 오래된 한도 값으로는 예상을 내지 않음.
  - `plan_order_claude`: `Pro, Max, Ultra`. 아래에서 위로 플랜 순서.
  - `plan_order_codex`: `plus, pro`. 아래에서 위로 플랜 순서.

## Review Focus

1. **Sheets turns `2026-11-16` text into a Date cell** when a date column isn't plain text, or when the owner retypes a cell. Every read must go through `cellToDateString`, which accepts both a `Date` and a string. Pinned in Task 2.
2. **The source jitters `resets_at` by seconds between reads.** Two reports 30 s apart must land in one limits row, not two weekly windows. Pinned in Tasks 1 and 2.
3. **The owner types a bad settings value** (`""`, `"70%"`, `"abc"`, a negative number). Each key must fall back to its default, never throw, and never produce a NaN category. Pinned in Task 2 (`parseSettings`) and Task 4.
4. **Month boundaries.** On the 1st, "이번 달" is a single day, and its comparison is the 1st of the previous month. On March 31 the comparison is clamped to Feb 28/29. "지난달" on January 1 is December of the previous year. Pinned in Task 3.
5. **A team ID or merge target the owner made inconsistent:**
   - a 합칠대상 cycle (A→B, B→A);
   - a merge target that doesn't exist;
   - two team IDs with the same 부서이름.

   None may loop or crash. Cycles and missing targets resolve to the person themselves, and same-named teams combine. Pinned in Task 3.

### Task 2: Store, device check and web app

**Files:**
- Create: `tools/usage-sheet/src/20_store.js`, `tools/usage-sheet/src/60_webapp.js`
- Modify: `tools/usage-sheet/test/harness.js` (fakes), `tools/usage-sheet/dist/Code.gs` (rebuild)
- Test: `tools/usage-sheet/test/store.test.js`

**Interfaces:**
- Consumes: `parsePayload`, the config constants and `localDateString` from Task 1.
- Produces:
  - `ensureSheets(ss): void`.
    - It creates every missing data tab (`원본`, `한도`, `사람`, `부서`, `팀이름`, `기기`, `설정`) with its header row.
    - It sets `@` on the date columns, hides `팀이름` and `기기`, and writes the default settings rows only when `설정` is new.
    - It is idempotent.
  - `handleReport(ss, text, nowMs, tz)`. It returns the response object from the contract.
    - It takes the script lock (`LockService.getScriptLock().waitLock(20000)`, released in `finally`).
    - It checks the device, then upserts raw rows, limit rows, people and team labels.
    - It adds new team IDs to `부서` with `처음본날`.
  - `doPost(e)` → `ContentService.createTextOutput(JSON.stringify(handleReport(SpreadsheetApp.getActiveSpreadsheet(), e.postData.contents, Date.now(), Session.getScriptTimeZone()))).setMimeType(ContentService.MimeType.JSON)`. It returns `{ok:false,error:"bad_json"}` when `e.postData` is missing.
  - `doGet()` → text `ok`.
  - `cellToDateString(v, tz): string`. A `Date` becomes `localDateString`. A string is trimmed and returned. Anything else becomes `""`.
  - `parseSettings(rows: any[][]): object`.
    - It maps each key to its value. Numeric keys fall back to their default when blank, non-finite or negative; `"70%"` becomes 70.
    - `plan_order_*` values are split on commas and trimmed into arrays.
    - Keys missing from the sheet get their defaults.
  - `readAll(ss, tz)`. Values are normalized: dates via `cellToDateString`, numbers via `Number`, and `resetsAt`/`lastReadAt` as epoch milliseconds. It returns:
    - `usage: [{ memberId, date, tool, team, total }]`;
    - `limits: [{ account, tool, resetsAt, memberId, team, plan, domain, maxUsed, lastUsed, lastReadAt }]`;
    - `people: { [memberId]: { nickname, mergeInto } }`;
    - `depts: { [team]: { name, suggested } }`;
    - `teamLabels: [{ team, memberId, label }]`;
    - `settings: parseSettings(...)`.

Rules:
- **Raw rows.** `합계` is the sum of the four counts. `받은시각` is an ISO `nowMs`. An existing key is overwritten in place and a new key appended.
- **Limit rows.** On an existing key, `최고사용률 = max(old, new)`. `마지막사용률`, `마지막읽은시각`, `플랜`, `memberId`, `팀ID` and `이메일도메인` take the new values, except when the incoming `readAt` is older than the stored `마지막읽은시각`. In that case only `최고사용률` may change.
- **Device check.** Hash with `Utilities.computeDigest(Utilities.DigestAlgorithm.SHA_256, secret, Utilities.Charset.UTF_8)`, then convert to lowercase hex.
  - On the first sight of a `memberId`, insert the hash.
  - On a match, update `마지막본시각`.
  - On a mismatch, return `device_mismatch` and write nothing.
- **People.** Upsert 닉네임, 마지막받은시각, 앱버전 and 플랫폼. Never touch 합칠대상.
- **Team labels.** Upsert by `팀ID|memberId`, and only when the label is non-empty.

**Interfaces:**
- Consumes: `readAll` output (Task 2), `DASHBOARD_TABS`, and `localDateString`.
- Produces:
  - `periodRange(kind: "thisMonth"|"last7"|"lastMonth", today: "yyyy-MM-dd")` → `{ start, end, prevStart, prevEnd, title }`. All dates are `yyyy-MM-dd` and inclusive.
    - `thisMonth`: month start to today. The comparison is the previous month's days 1 to min(today's day, previous month length).
    - `last7`: today − 6 to today. The comparison is the 7 days before.
    - `lastMonth`: the whole previous month. The comparison is the whole month before it.
    - `title` is, for example, `"이번 달 (2026-11-01 ~ 2026-11-16)"`.
  - `canonicalPerson(memberId, people): string`. It follows `mergeInto` up to 5 hops. A cycle or a missing target returns the last valid id before the problem, or the id itself.

  - `computeDashboard(data, kind, today)` → `{ title, tiles, teams, top, bottom, unassigned }`.
    - `tiles`: `{ total, perPerson, people, teamCount, deltaTotalPct, deltaPerPersonPct, deltaPeople }`.
    - `teams`: `[{ name, total, perPerson, people }]`, sorted by total desc.
    - `top` and `bottom`: `[{ nickname, team, total }]`.
    - `unassigned`: `{ people, total }`.
  - `renderDashboard(sheet, model, nowMs, tz)`.

Rules (spec 9장):
- **What counts.** Only rows dated in the range count. A row's department is `depts[team].name`, trimmed. A row whose department is empty is **unassigned** and is excluded from everything except `unassigned`. Teams with the same department name combine (Review Focus 5).
- **Person.** A person is `canonicalPerson(memberId)`. The nickname comes from the canonical person's `people` row, falling back to the first 8 characters of the id.
- **Tiles**
  - `people` is the number of distinct persons with ≥1 assigned row in the range. A person whose only rows are `-` zero rows still counts.
  - `total` is the sum of `total`. `perPerson` is `total / people`, or 0 when there are no people.
  - `teamCount` is the number of departments with ≥1 row.
  - The deltas compare with the comparison range using the same rules: percent change rounded to 0.1, or `null` when the comparison value is 0. `deltaPeople` is the difference in people.
- **Teams.** `team.people` is the number of distinct persons with ≥1 row in that department, and `perPerson` is `total / people`.
- **Person's team.** It is the department with the most distinct dates for that person in the range. Ties go to more tokens, then to the name in ascending order.
- **Top and bottom.** `top` is the 5 highest totals, ties by nickname ascending. `bottom` is the 5 lowest totals, ties by nickname ascending, excluding anyone already in `top`.
- **Layout** (`renderDashboard`; the sheet is cleared first and every chart removed)
  - A1: title. A2: `마지막 갱신: yyyy-MM-dd HH:mm`.
  - A4:D4: `전체 토큰`, `1인 평균`, `쓰는 사람`, `팀 수`. A5:D5 holds the values and A6:D6 the deltas as text: `+18.0%`, `−6.0%` or `—`; people as `+4명`.
  - A8:D8: `부서`, `총 토큰`, `1인 평균`, `인원`, then the team rows.
  - F8:H8: `많이 쓰는 팀원`, `부서`, `토큰`, rows F9:H13. F16:H16: `적게 쓰는 팀원`, `부서`, `토큰`, rows F17:H21.
  - The line after the team rows plus one blank row reads `미지정: N명 · X 토큰 — 부서 탭에 이름을 적으면 포함됩니다`.
  - Below that, the three notes from spec 9장 "대시보드에 적어 둘 안내".
  - Token cells use the number format `#,##0.0,,"M"`.
- **Charts.** Two bar charts: departments against 총 토큰, and departments against 1인 평균. Each range is exactly the header plus the team rows. They are placed to the right of the top and bottom tables. With no teams, no charts are added.

### Task 4: Plan tab

**Files:**
- Create: `tools/usage-sheet/src/40_plan.js`
- Modify: `tools/usage-sheet/dist/Code.gs`

**Interfaces:**
- Consumes:
  - `readAll` output;
  - `canonicalPerson` and `departmentOf` from Task 3, reused rather than reimplemented.
- Produces:
  - `computePlan(data, nowMs)` → `{ tiles: { short, fit, spare, noInfo }, rows, excludedAccounts }`.
    - Each row is `{ nickname, team, tool, plan, domain, usedPct, daysToReset, pacePct, projectedPct, forecast, fullWeeks, finishedWeeks, suggestion }`.
    - `excludedAccounts` counts the accounts left out because their department is unassigned.
  - `renderPlan(sheet, model, nowMs, tz)`.

Rules (spec 9.1장). `s` is `data.settings`, and the window span is 7 days.
- **Accounts and windows.** Group limit rows by `account|tool`.
  - The **current window** is the row with the smallest `resetsAt` > now.
  - **Finished windows** are rows with `resetsAt` ≤ now, newest first, taking `s.suggest_weeks` of them.
  - An account's person, team and plan come from its most recent row by `lastReadAt`.
  - Accounts whose department is unassigned are left out and counted in `excludedAccounts`.
- **Pace and projection.** `pace = (span − (resetsAt − lastReadAt)) / span`, from the current window, with `pacePct = pace × 100`.
  - `projectedPct = lastUsed / pace`.
  - It is `null` when there is no current window, when `pace < s.min_pace` or `pace > 1`, or when `now − lastReadAt > s.stale_hours` hours.
- **`forecast`**, the first rule that matches:
  1. `"이미 다 씀"` if `lastUsed ≥ s.full_week_pct`;
  2. `"—"` if `projectedPct` is null;
  3. `"모자람"` if `≥ s.forecast_short_pct`;
  4. `"알맞음"` if `≥ s.forecast_fit_pct`;
  5. otherwise `"남음"`.
- **Weeks.** `fullWeeks` counts the finished windows with `maxUsed ≥ s.full_week_pct`. `finishedWeeks` is how many finished windows were found.
- **`suggestion`**
  1. `"기록 부족"` if `finishedWeeks < s.suggest_weeks`.
  2. If `fullWeeks ≥ s.suggest_up_full_weeks`: `"올리기 검토 → <next plan>"`. Use `"최상위 플랜"` when the plan is last in `plan_order_<tool>`, and plain `"올리기 검토"` when the plan isn't in the list.
  3. If every finished window's `maxUsed < s.suggest_down_max_pct`: `"내리기 검토 → <previous plan>"`. Use `"필요한지 검토"` when the plan is first in the list, and plain `"내리기 검토"` when it isn't in the list.
  4. Otherwise `"유지"`.
  - Plan names match case-insensitively. The `plan_order_<tool>` lookup for Claude limits uses the tool id `claude`.
- **Tiles.** Count distinct persons by their worst account forecast. The order is 이미 다 씀 and 모자람 (both `short`), then 알맞음 (`fit`), then 남음 (`spare`). `"—"` counts in none of them.
  - `noInfo` counts persons who have usage rows in the last 7 days in an assigned department but no limit row with `lastReadAt` in the last 7 days.
- **Sorting.** Forecast rank (이미 다 씀, 모자람, 알맞음, 남음, —), then `projectedPct` desc with null last, then nickname.
- **Layout** (`renderPlan`; cleared first)
  - A1: `플랜과 주간 한도 — 지금 진행 중인 주`. A2: `마지막 갱신: …`.
  - A4:D4: `이번 주 모자랄 사람`, `알맞게 쓸 사람`, `남길 사람`, `플랜 정보 없음`, with the values on row 5.
  - Header on row 7: `닉네임`, `부서`, `도구`, `플랜`, `이메일 도메인`, `이번 주 사용`, `막대`, `균등하게 썼다면`, `리셋까지(일)`, `이 속도면 리셋 때`, `예상`, `지난 4주 중 다 쓴 주`, `제안`.
  - Rows start at 8.

    - The percentage cells use the format `0%` on value/100, or show the number with `"%"`; either is fine but stay consistent.
    - `지난 4주 중 다 쓴 주` is the text `"<fullWeeks> / <suggest_weeks>"`.
